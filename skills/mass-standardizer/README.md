# 🏭 Mass Standardizer

Automated engine for the batch normalization of the Token-Optimized Agent Pipeline's skill library.

## About The Project

The **Mass Standardizer** is the enforcement arm of technical sovereignty hardening. Its goal is to eliminate architectural debt through automated injection of the documentation and structure standards defined by `skill-creator`.

**Key Features:**
- **Audit & Detect**: Identifies skill folders that lack the official structure (Three-File Skill Standard, agents.md §3).
- **Template Synthesis**: Injects standardized `README.md` and `SKILL.md` files.
- **Topological Enforcement**: For executable skills, guarantees the presence of the `/scripts/` directory and `__init__.py`. Knowledge skills are left alone — `agents.md §3` prohibits padding them with empty scaffolding.
- **Vendored Content**: A skill shipping its own `SKILL.md` below its root has the root file point at it — so the manifest and Claude Code's discovery read the skill rather than a generated stub — **but only when that root file is absent or is this script's own untouched scaffolding**. Anything else is content somebody wrote: it is reported as `[!] … left untouched, resolve by hand.` and never deleted. `skills/django-expert-3rd/` is the one skill in this library that vendors. Its root file was authored rather than scaffolded, so this script reported it and refused to touch it; a human then relocated its directives to `rules/django_backend_standard.md` and repointed the root by hand (Sprint 023 `C4.2`), which is the resolution the `[!]` line asks for.

## Getting Started

### Prerequisites
- Access to `manifest_skills.json`.
- Write permission on the flat `skills/` directory.

## Usage

Invoked by a human during refactor sprints or full pipeline unification passes. The script takes no arguments — it standardizes every skill `manifest_skills.json` lists — and it anchors to the framework, so it may be run from any working directory:

```bash
python3 skills/mass-standardizer/scripts/mass_standardizer.py
```

| Exit | Meaning |
| :--- | :--- |
| `0` | Every listed skill was processed |
| `1` | `manifest_skills.json` is absent; nothing was standardized |

A manifest that exists but is malformed raises instead, deliberately: the file is generated by `generate_manifest.py` and checked by `check_manifest_parity.py`, so a corrupt one is a broken repository rather than a condition this script should absorb.

The `--all` flag this section documented until Sprint 023 was never implemented and was silently ignored.
