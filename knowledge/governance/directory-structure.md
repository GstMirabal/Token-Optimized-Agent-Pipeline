# 🧠 Knowledge Item: Governance Directory Structure

## Status
- **Date**: 2026-03-30
- **Context**: Sprint 001 - Stabilization & I18n.
- **Problem**: root-level `.agents` directory was becoming cluttered with ephemeral task logs and internal agent assets, mixing "process" with "governance".

## Solution: Professional Layered Governance
The project now follows a strict segregation policy to ensure Git cleanliness and agent portability:

### 1. Persistent Layer (`.agents/governance/`)
Contains the "brain" of the agentic system. Any file that dictates behavior or provides long-term context must be here.
- `global_user_rules.md`: Naming conventions, coding standards, and directory rules.
- `agents_roadmap.md`: Meta-roadmap of the agentic infrastructure.
- `subagents_architecture.md`: Workflow definitions (Mentor > Orchestrator > Auditor).

### 2. Ephemeral Layer (`.agents/sprints/`)
Contains current and historical execution data.
- Format: `XXX-sprint-name.md` for task logs and `XXX-sprint-plan.md` for implementation plans.
- Root `.agents/task.md` must be a Table of Contents (TOC) pointing to these files.

### 3. Deliverable Layer (`docs/`)
Only high-value technical assets resulting from specific tasks.
- Audit Reports, Architecture Flows, and domain diagrams belong here (e.g., `docs/EN/MASTER_AUDIT_REPORT.md`).
