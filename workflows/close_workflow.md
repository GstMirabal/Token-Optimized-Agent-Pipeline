# 🛡️ Workflow: Close (Session Close)

Master closure protocol enforcing the Zero-Tolerance Memory Purge rule, Absolute Topographic Purity, and Git state sovereignty.

## Execution Flow

| Phase | Step | Action / Constraint |
| :--- | :--- | :--- |
| **0. Ruleset Invocation** | `read_ruleset` | Verify the governance ruleset is in context (auto-imported via the host `CLAUDE.md`); a full re-read is only required after context compaction (`anti_amnesia`) — re-reading an already-loaded document is a token violation, not diligence. Closure actions omitting governance compliance are invalid. |
| **1. Topographic Audit** | `noise_purge` | **MANDATORY**: Delete all empty folders (RA-07). Validate all new files follow **Option B Naming** (`[MODULE]_[TYPE].md`). |
| **1. Topographic Audit** | `rules_optimization` | Optimize rules via `skills/skillopt/scripts/train_runner.py` if failures or governance rule changes occur (requires explicit authorization). Full path because the file is not in a directory a bare name resolves to — see the citation convention in `rules/qa_and_testing.md`. |
| **1. Topographic Audit** | `graph_rebuild` | Run `make -f .agents/Makefile graphify-update` to sync AST changes. Run the semantic rebuild via `make -f .agents/Makefile graphify-rebuild` if documentation has been modified. |
| **1. Topographic Audit** | `docs_freshness_gate` | Persist `graph_stats.json` inside the sprint directory named canonically in `agents.md §5 mandatory_topology` (git-tracked snapshot of node/edge/community counts — the only source `docs-freshness-check` trusts, never `graphify-out/`, which is gitignored). Run `make -f .agents/Makefile docs-freshness-check SPRINT_ID=[ID]` (`rules/documentation_standard.md §4`). First cycle a host adopts this gate: findings are `WARN` only. From the second cycle: a `BLOCK` finding halts Phase 6 (`SESSION LOCKED`) until resolved. **Verify the snapshot actually moved**: if this sprint changed source files and the node/edge/community counts are identical to the previous snapshot, the rebuild did not happen — a graph "rebuilt" into unchanged numbers is a rebuild that silently no-opped. **Applies in nucleus mode too.** This said *host-only* because the nucleus had no `docs/sprints/` hierarchy — it does since Sprint `024`, which found the exclusion that prevented it was hiding host contamination from `submodule_purity` rather than preventing it (`agents.md §5 mandatory_topology`). Leaving these two steps marked host-only would keep skipping in the nucleus the very gates that sprint revived. |
| **2. Sprint Closeout** | `history_sync` | Update the **Master Ledger** (host root `CHANGELOG.md`: append this sprint's entry under `[Unreleased]`, referencing `#[Sprint_ID]`), the **Global Roadmap**, **Module Walkthroughs**, and — **explicitly, not by inference** (a prior host let these go stale for 34 sprints because this list never named them) — the **Documentation Entry Point anchors** (`0_SYSTEM_OVERVIEW.md`, `0_SYSTEM_ARCHITECTURE.md`) whenever this sprint touched structure, stamping their `**Last Audit Sprint**`/`**Last Audit Date**`/`**Last Audit Commit SHA**` fields (`rules/documentation_standard.md §4.1`). **The two Entry Point anchors are host-only**: they do not exist in the nucleus and are not supposed to — they are scaffolded into a host by `standardization_workflow.md`. A close running in the nucleus that goes looking for them is chasing files by design absent, the same nucleus/host asymmetry that made `make verify` fail from every invocation path before `v4.3.0`. The Master Ledger, Global Roadmap and Walkthroughs apply in both modes. |
| **2. Sprint Closeout** | `readme_counts` | Run `python3 .agents/scripts/check_readme_counts.py`. **Exits `2` on drift.** The README declares how many rule contexts, agents, skills, workflows and commands ship; nothing recalculated them, so they drifted silently and were corrected by hand three times in one session. Deterministic and therefore not delegated to judgment (`token_economy_agent` Filter 5). The table's "8 phases" line is **not** checked: it is prose about a workflow's internals, not a countable set, and a check that claims to verify what it never measured is the `#28` defect. |
| **2. Sprint Closeout** | `repo_docs_check` | Confirm `CONTRIBUTING.md`, `SECURITY.md`, `CODE_OF_CONDUCT.md` and `NOTICE.md` exist (mechanical), **and** — this part is deliberately judgment, not a script — decide whether this sprint's work invalidated any of them: a new vendored dependency changes `NOTICE.md`, a changed reporting channel changes `SECURITY.md`, a changed contribution gate changes `CONTRIBUTING.md`. Presence is checkable; relevance is not, and pretending otherwise would produce a green check over stale content. |
| **2. Sprint Closeout** | `extract_handoff` | Run `/agents:extract` (see `extract_workflow.md`) to decide what survives into `memory_index.json` before the purge below destroys the raw logs. |
| **2.5 Heuristic Pulse Gate** | `heuristic_pulse_gate` | Present the human with the exact list of candidate KIs `extract_handoff` decided survive into `memory_index.json`, and wait for explicit confirmation before Phase 3 executes — the same `RA-13 SEQUENTIAL_GATES` principle (a verification and the irreversible action it guards must be observed separately) applied to `memory_wipe` instead of a merge. **Exception**: when this session is running under Claude Code's `/loop` (Phases 6-8 unattended, per `pipeline_workflow.md`), this gate does not block — log the candidate KI list and proceed, so multi-sprint automation isn't stalled waiting on a human who isn't watching. Outside `/loop`, this is a hard stop. |
| **2.6 Phase Completion Gate** | `double_gate_evidence` | Before Phase 3 executes, verify this sprint's record proves Phases 4 and 7 ran: the sprint directory named in `agents.md §5 mandatory_topology` MUST contain `task_scope.md` (Rule Validator, Phase 4), and the sprint record MUST state one QA verdict and one Tester verdict (Phase 7). A phase that left no artifact did not run. If either is absent, **refuse the close**, name the missing phase, and run it. **Applies in nucleus mode too.** This said *host-only* because the nucleus had no `docs/sprints/` hierarchy — it does since Sprint `024`, which found the exclusion that prevented it was hiding host contamination from `submodule_purity` rather than preventing it (`agents.md §5 mandatory_topology`). Leaving these two steps marked host-only would keep skipping in the nucleus the very gates that sprint revived. Rationale: every other control here inspects the *content* of what was written and none asks whether the step that writes it executed, so a host ran an entire sprint without Phases 4 and 7 and no gate detected it across twelve commits. `jurisdictional_lock` and `no_interference` are both applied by *reading* `task_scope.md`, so skipping the phase that produces it disabled two isolation rules while they still appeared to be in force. |
| **3. Zero-Tolerance Purge** | `memory_wipe` | Execute forced physical deletion (`rm`) of all temporary logs within the `/memory/` sprint directory. **Host-only in practice**: the nucleus has no `memory/` directory — `hooks/telemetry.py` creates `memory/telemetry/` on the first logged error and nothing else populates it. When the directory is absent this step is a no-op, and saying so is the point: a step that silently does nothing is indistinguishable from a step that failed. |
| **3.5 Platform Recheck** | `platform_recheck` | Run `python3 .agents/scripts/session_probe.py --force-platform`. The session close is the event that invalidates the 7-day cache used at `start`: a sprint is exactly when a dependency was added, a required check name changed, or the reporting channel moved. Advisory, like every probe. |
| **4. State Sync** | `state_sync` | **`release` seals the SPRINT; `suspend` ends the SESSION. They are not interchangeable and the difference is `last_close_commit`**: `release` writes it, `suspend` deliberately does not, because that field means "the commit where the last close sealed" and writing it at a session boundary sets a false baseline that blinds `detect_drift.py`. Wire a session-end event to `suspend`, never to `release` — the Sprint 027 design in the program roadmap did the latter and would have written a false seal at the end of every session. Release the session lock with `python3 .agents/scripts/session_state.py release` — it sets `CLOSED_SUCCESSFULLY`, stamps `end_time`, records **`last_close_commit`** (the SHA this close sealed at; anything committed after it happened outside the protocol) and refreshes the mirror. Then update sprint status and `topology_version` in `docs/active_state.json`, **and refresh the mirror again** (`python3 .agents/hooks/state_mirror.py` — in the nucleus: `python3 hooks/state_mirror.py`; hosts also get it automatically via the Stop hook). **Applies in nucleus mode too** — the nucleus keeps its own local anchor, and a stale anchor or mirror lies to the next session. |
| **5. Git Sovereignty** | `atomic_commit` | Execute atomic `git commit` and `git push origin ai-sprint/[ID]` — **never `main`/upstream directly** (RA-12 Branch Discipline). Merging `ai-sprint/[ID]` into `main` is exclusively `deployment_workflow.md`'s job. |
| **5. Git Sovereignty** | `submodule_purity` | Run `python3 .agents/scripts/submodule_purity.py`. **Exits `2` and the close stops** when a host session has content inside the framework submodule (`agents.md §3 strict_rule`). It reports *what* dirtied it, because the two cases have different remedies: a **modified tracked file** is a host editing the framework in place — that change belongs in the nucleus repository via `§4 feedback_upstream`, reaching this host later as a deliberate pin bump (`start_workflow.md lightweight_sync`); **untracked files** are a host sprint's records written into the wrong repository — they belong at the HOST root (`agents.md §5`). In nucleus mode it is a no-op: there is no submodule to protect and the framework's own records belong here. **This was a sentence until Sprint 025** — *"verify `git -C .agents status --porcelain` is clean"*, with no script, flagged by `scan_workflow_determinism.py` in every `make verify` run and never actioned — and until Sprint 024 that command was **blind**, because `.gitignore` excluded exactly the paths a host writes and `--porcelain` does not list ignored files. |
| **5.5 Branch Sovereignty** | `branch_audit` | Run `python3 .agents/scripts/branch_sovereignty.py audit`. **Exits `2` and the seal is refused** while any local branch still holds work not in the base branch — including branches from earlier sprints, not just this one's. **Not scoped to `ai-sprint/*`**: this repository has never used that prefix, and a check scoped to a naming convention the repository does not follow reports clean on a dirty tree. **Not `git branch --merged` either**: `deployment` merges with `gh pr merge --squash`, and a squash merge leaves the branch permanently absent from `--merged`, so that instrument would denounce integrated branches forever and prune nothing. Integration is proven by merged-PR state first and `git cherry` as the offline fallback. **The lookup answers in three values, not two, and the third is the point**: `yes`, `no`, and `could not determine`. Collapsing the third into `no` is what made this gate intermittently accuse healthy branches — measured at **2 failed calls in 12** (`HTTP 503`), and reproduced as two triple-runs on an unchanged tree exiting `0,2,0` and `0,0,2` while naming a *different* branch each time. An undetermined branch **still refuses the seal**, because unproven is not clean, but it is reported as doubt rather than as an accusation and **is never offered a waiver** — the waiver is permanent, and the branch may be perfectly integrated. Re-run the check instead; the cause is usually transient. Conversely, a repository with **no GitHub remote at all** is a definitive `no`, not a doubt: no pull request can exist there, and treating it as undetermined would refuse every close in every local-only repository forever. **The checked-out branch is excluded, and that is not a weakening**: this step runs while the sprint branch holds the sprint's own commits, and Phase 6 below states that branch stays unmerged until `deployment_workflow.md` integrates it — so auditing it refused the seal for the very branch being sealed, verified on `ai-sprint/024`. The exclusion is positional: the same branch blocks again the moment it stops being `HEAD`, which is the leftover-from-an-earlier-sprint case this gate exists for. |
| **5.5 Branch Sovereignty** | `local_prune` | `python3 .agents/scripts/branch_sovereignty.py prune` deletes only branches whose integration was **proven**, and prunes dead remote-tracking refs. Work that was not proven integrated is never touched — it is reported, and a branch whose state could not be **determined** is reported separately from one proven unintegrated, because deletion is irreversible and a lookup that did not answer must never authorise it. A branch genuinely abandoned is declared in `config/abandoned_branches.json` with a reason: without that valve, one forgotten branch would block every future close, and a gate with no answer is a gate that gets disabled. **The valve is for abandonment, never for doubt** — waiving an undetermined branch silences one that may be perfectly integrated, permanently. Re-run the check instead. |
| **6. Session Lock** | `deployment_handoff` | **Name the next protocol, do not merely name the jurisdiction.** The sprint branch is pushed and unmerged; integrating it is `workflows/deployment_workflow.md` (`/agents:deployment`), which is where the Tester signature and the observed-green CI gate live (`RA-13`). Until Phase 019 this workflow said only that merging was "exclusively deployment's job" — a statement about ownership, not a transition — and the branch therefore survived every close by design. That is how sprint branches accumulate. |
| **6. Session Lock** | `session_lock` | Output the official seal: **`SESSION LOCKED`**. The pipeline enters suspended animation. |
