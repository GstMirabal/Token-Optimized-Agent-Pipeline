# 🛡️ Workflow: Start (Pipeline Initiation)

Master entry protocol optimized to minimize token consumption and strictly invoke the execution pipeline.

## Execution Flow

| Phase | Step | Action / Constraint |
| :--- | :--- | :--- |
| **0. Zero-Memory Initialization** | `read_anchor` | Subagents MUST initialize with **Zero-Memory**. The absolute first operation is to extract the topology map from `docs/active_state.json` (if it doesn't exist yet, see `first_run_scaffold` below). **Mirror reconciliation**: if `.agent_state/mirror.json` disagrees with the anchor, this is NOT a collision — the anchor wins (the mirror is the backup; staleness only means a previous session ended without the Stop hook firing). Resync it (`python3 .agents/hooks/state_mirror.py`) and continue. The mirror is only authoritative when the anchor itself is missing or corrupt (crash recovery). |
| **0. Zero-Memory Initialization** | `read_ruleset` | Immediately after the anchor, read `agents.md` and `docs/0_SYSTEM_OVERVIEW.md` to adopt current governance. **In nucleus mode the second file does not exist and is not supposed to** (`agents.md §0`, which names the substitute): read `agents.md` plus `docs/guides/WORKFLOWS_STEP_MAP_GUIDE.md`. Without this clause the step could not be satisfied here at all — sessions #2 through #5 of Sprint 023 each hit this gap and each re-derived the same answer. |
| **0. Zero-Memory Initialization** | `pip_setup` | Check if `.agents/installed.lock` exists. If not, create virtual environment `.agents/venv_skillopt/`, install the lean core with `.agents/venv_skillopt/bin/pip install -r .agents/requirements-core.txt`, and write `.agents/installed.lock` recording the ISO timestamp and the requirement set installed (so a later reader knows *what* this environment contains). The heavy skillopt stack (`requirements-skillopt.txt`) installs on demand only when that skill first runs. |
| **0. Zero-Memory Initialization** | `read_graph` | Skip graph construction on tiny hosts (fewer than ~25 source files — a targeted grep is cheaper than building and loading a graph). Otherwise, if `graphify-out/graph.json` is missing, build it with `.agents/venv_skillopt/bin/graphify update .`; if present, query it via MCP/CLI to align on boundaries. |
| **0.4 Drift Check** | `drift_check` | Run `python3 .agents/scripts/detect_drift.py`. It compares `last_close_commit` against `HEAD` and **reports a verdict, not a boolean** — a non-empty range is not drift by itself, because `deployment_workflow.md` Phase 4 seals `[Unreleased]` into a released section and tags it without touching `last_close_commit`, so recorded commits keep landing after the last close. The range is split against **sealing tags** (tags whose version owns a `## [X.Y.Z]` section) and the exit code follows the action required: **`S`** every commit covered → `0`, reports and proposes refreshing the baseline; **`M`** partially covered → `2`, lists only the uncovered; **`U`** none covered and `[Unreleased]` empty → `2`; **`A`** uncovered commits with `[Unreleased]` non-empty → `2`, they may be recorded there but reachability cannot prove it per commit; **`R`** no tag owns a section → `2`, nothing proves any of them recorded. **On any `2`, run `/agents:reconcile` before Phase 2 handoff**, because new work stacked on a state that misreports the repository multiplies the inconsistency instead of resolving it. **An orphaned baseline degrades, it does not lie**: `close_workflow.md` Phase 4 records HEAD on the sprint branch and deployment squash-merges it, so the recorded commit stops being an ancestor of the base branch — the check falls back to their merge-base and says so, because `git cat-file -e` cannot detect this (the orphaned object still exists). Reachability proves the **range** is covered, never that each commit has its own entry: PRs `#26`-`#30` were ancestors of a tag and still unrecorded, and the `S` report states this. Rationale: `docs/decisions/ADR-0002-drift-verdict-exit-codes.md`. **This runs BEFORE `state_claim`, never after**: claiming the lock sets `status: IN_PROGRESS`, and a check keyed on the previous status would be reading its own side effect. Without a baseline recorded yet it says so and passes, rather than staying silent — silence is what let five merged pull requests go unrecorded for a week. |
| **0.5 State Claim** | `state_claim` | **Write the anchor. This workflow used to write nothing at all** — all nine of its steps read or verified, so `session_id` was always the *last closed* session's, never the running one. Run `python3 .agents/scripts/session_state.py claim` (nucleus: `python3 scripts/session_state.py claim`), with `--session-id` and `--tool` chosen as named below. It sets `status: IN_PROGRESS`, records the session's UID, its `session_tool`, and `start_time`, and refreshes the mirror. Claiming the lock and recording the session are the same act, so they are one command and not two steps rewriting one file. **`--session-id` is optional** (`required=False, default=None`): supply it when the harness exposes one, omit it when it does not, and `claim()` mints a UID itself in that case — form `<compact UTC ISO-8601 basic>-<PID>`, e.g. `20260824T161231Z-86137` — recorded in the anchor exactly as a supplied UID would be. **`--tool`** records which harness is claiming the lock as `session_tool`, next to `session_id`: one of `claude-code|cursor|terminal`, default `terminal`. **`--delegation-mode` is optional**, values `native|sequential`: omitted, it derives from `--tool` — `cursor` yields `sequential`, every other tool yields `native`; supplied explicitly, it overrides the derivation. Written to `delegation_mode` in the anchor; `delegation_conflict` below documents what the value means and when its divergence from actual capability must be reported. **Named per harness, so the invocation never requires inference**: under Claude Code, `python3 scripts/session_state.py claim --session-id <this session's UID> --tool claude-code`; under Cursor, which exposes no session UID to the harness, `python3 scripts/session_state.py claim --tool cursor` with `--session-id` omitted; under a bare terminal or any other harness that exposes neither a UID nor a Cursor identity, `python3 scripts/session_state.py claim --tool terminal` with `--session-id` omitted. Exits `2` when another session holds the lock; `--takeover` seizes a lock left by a crashed session, and is deliberately manual because a live concurrent session and a dead one look identical from here. |
| **0.6 Readiness Probe** | `readiness_probe` | Run `python3 .agents/scripts/session_probe.py`. **Advisory: it proposes and never executes.** Reports a stale knowledge graph, absent documentation artifacts (`docs/decisions/`, Blueprints), an **anchor naming a different sprint than the checked-out `ai-sprint/[ID]` branch**, and — see `platform_probe` — platform controls. The anchor comparison exists because **opening a sprint writes no field of the anchor and no script does**: `session_state.py claim` now takes `--session-id` (optional), `--tool`, `--takeover` and `--delegation-mode` — none of them `current_sprint.id` — so `current_sprint.id` remains a hand edit with no gate, and Sprint 023's resume read `22` while `ai-sprint/023` and its sprint directory both already existed. This sprint's own unit `A1` corrected `current_sprint.id` from `23` to `26`, and `resume_pointer` from the deleted `ai-sprint/023`, by hand, for exactly this reason. It compares against the **branch**, not against the newest directory under `docs/sprints/`: those look equivalent and are not, since `024` and `025` exist here while `023` is legitimately in flight, so a directory-based check fires on a correct state. Proposing `/agents:revdoc` is as far as it goes: that protocol reads all of `docs/` and rewrites contracts in place, which `agents.md §2 triple_lock` reserves for human authorization. A gap the human has seen and accepted is recorded in `acknowledged_gaps` in the anchor, so the proposal stops repeating. |
| **0.7 Platform Probe** | `platform_probe` | Part of the same script. Checks secret scanning, push protection, Dependabot updates and alerts, branch protection, repository metadata and the community files, and proposes `/agents:harden`. **Cached for 7 days** (`last_platform_probe`): repository configuration changes a couple of times a year, and a check that fires every session is a check that gets ignored. **Skipped silently** when `gh` is absent or the remote is not GitHub. Community files are checked **against the tree, never against `community/profile`** — that endpoint reports `issue_template` as `null` whenever templates live in a directory, which is the current form, and this repository ships three while scoring `null` at 100% health. |
| **1. Collision Guard** | `session_lock_check` | Abort if `status` in `docs/active_state.json` is `IN_PROGRESS` under a different session UID (crash forensics). **`SUSPENDED` is not a collision — it is a resume.** Sprint 021 made the session bound binding per context cycle, so a sprint can now be cut mid-flight and continued: `suspend` ends the session without sealing the sprint, and `claim` over that state proceeds, reports the resume and increments `session_count`. Before that state existed, a planned handoff and a crashed session were indistinguishable from here and the second session had to declare itself crash recovery. **On a resume, read the Implementation Plan, `task_scope.md` and `resume_pointer` before starting new work**: the conversation did not survive the boundary, the record did. **The check is now armed**: `state_claim` above is what writes that state — before Phase 019 nothing anywhere did, so this guard could never fire. **Nucleus mode** (`.git` is a real repo directory, not a submodule pointer — same check the installer uses): Phase 0 and `lightweight_sync` run normally, with `.agents/`-prefixed paths resolving to the repo root (e.g. `./venv_skillopt/`). Of Phase 1.5, **only `first_run_scaffold` is PROHIBITED** — `nucleus_neutrality` (`agents.md §5`) prohibits *structural scaffolding*, and `bridge_check` is not scaffolding. `scripts/install.py` says so in the code that implements it (`install_nucleus_bridge()`: *"nucleus_neutrality governs structure, not tooling access"*), ships a minimal nucleus self-bridge for exactly this purpose, and `tests/test_installer.sh` pins its behaviour. **This row used to prohibit all of Phase 1.5**, and the cost was measured in Sprint 023 `C6`: the nucleus bridge was installed once in July and never refreshed, so `commands/` held thirteen files while `.claude/commands/agents/` held eleven stale symlinks — `/agents:reconcile`, `/agents:harden` and `/agents:revdoc` were not typeable in the nucleus, including the one `drift_check` above mandates on exit `2`, plus a dangling `skeleton.md` whose source no longer exists. |
| **1. Collision Guard** | `lightweight_sync` | Run `python3 .agents/scripts/sync_agents_pin.py` (nucleus: `python3 scripts/sync_agents_pin.py`). **Ping** (`git fetch --tags` of `origin`, 20s, `GIT_TERMINAL_PROMPT=0`): unreachable origin keeps the current pin and start continues. If a newer **version tag** (`vX.Y.Z`) exists than `describe --tags --abbrev=0`, **checkout it automatically** (O6; tags only, never `main`). Dirty `.agents` while behind → exit `2`, do not overwrite. Nucleus: no-op (`git describe` ahead of the latest tag is not drift). After a bump, `bridge_check` re-links (lock commit differs). The host gitlink stays dirty until the host commits the pin. The script prints `.agents/CHANGELOG.md`; if `agents.md §0` Rule Contexts gained a file, name it (advisory). On exit `2`, stop Phase 2 handoff until the tree is clean. |
| **1.5 Bridge Provision** | `bridge_check` | Run `.agents/scripts/install.sh --target claude` when `session_tool` is `claude-code`, or `.agents/scripts/install.sh --target cursor` when `session_tool` is `cursor`, if the lock for **this session's own target** is missing — `.agents/.bridge_claude.lock` for a Claude Code target, `.agents/.bridge_cursor.lock` for a Cursor target, chosen by the `session_tool` this session recorded at `state_claim` above — its recorded commit differs from `git -C .agents rev-parse HEAD` (i.e. the submodule was deliberately updated since the last install — new agents/commands/skills need linking), **or** the linked artifacts themselves are gone from `.claude/` (or `.cursor/`, for a Cursor target) despite a matching lock (a `git clean -fd`/manual deletion wipes the host's untracked bridge without touching the lock, which lives inside the submodule). The two locks are independent: installing one target's bridge does not mark the other target's lock current, so a host bridged for both tools carries both files and this step reads only the one matching its own session. The installer is idempotent; **in a host**, `hooks/on_init.py` performs this same check (`sync_commands` + `bridge_intact` sentinel) automatically at session start. **In the nucleus no hook runs at all**, and that — not the old prohibition alone — is why this bridge went stale for a month: `install_nucleus_bridge()` installs none by design (*"No hooks (paths are host-relative)"*), and no `settings.hooks.json` reaches the nucleus `.claude/`, so `SessionStart` is never registered; `hooks/on_init.py` also resolves `.agents/`-prefixed paths that do not exist here. A nucleus reader who assumed the automation covered them held exactly the belief that let the bridge rot. **In nucleus mode this step RUNS** (see the nucleus clause above) and takes a different trigger: `install_nucleus_bridge()` writes neither `.bridge_claude.lock` nor `.bridge_cursor.lock`, so a lock comparison is meaningless here. Run `scripts/install.sh --target claude` when `session_tool` is `claude-code` and `.claude/commands/agents/` does not hold one symlink per file in `commands/`; run `scripts/install.sh --target cursor` when `session_tool` is `cursor` and `.cursor/commands/` is missing or stale — the conditions that are actually true when the bridge is stale, and the ones that were silently true for a month. The installer relinks idempotently but **does not prune**: a symlink whose source was renamed or deleted survives as a dangling entry and must be removed by hand. |
| **1.5 Bridge Provision** | `first_run_scaffold` | If `docs/active_state.json` is missing, this is the first pipeline session in this host: load the **Onboarding Scenario Matrix** (`standardization_workflow.md` Phase 6) and route the detected scenario (greenfield / prior agents / mature) **before** Phase 2 handoff. The matrix lives there — not here — because first-run routing is a one-time cost while this workflow loads on EVERY session (`rules/token_economy.md §3`). |
| **1.6 Autonomy posture (Cursor)** | `cursor_memory_drift` | **Claude Code** applies Memory/Drift acceleration via `claude/settings.hooks.json` (`PreCompact` → `persist_session_context.py`, `SubagentStop` → `check_role_artifact.py --from-hook`, `SessionEnd` → `session_end_hook.py` / suspend). **Cursor does not read that file.** When `session_tool` is `cursor`, after any context compaction (or when resuming and the conversation no longer holds the sprint path): run `python3 .agents/scripts/persist_session_context.py` (nucleus: `python3 scripts/persist_session_context.py`), re-read `docs/active_state.json` and the printed `task_scope.md`, and treat `make role-artifacts ROLE=… SPRINT_DIR=…` as the phase-boundary Drift check (close Phase 2.6 remains the hard gate). Effectiveness (`defaultMode: auto`) has **no** Cursor counterpart — do not pretend settings cover it. Full map: `docs/guides/AUTONOMY_POSTURE_GUIDE.md`. |
| **2. Pipeline Handoff** | `pipeline_invocation` | Explicitly hand command to the **Principal Agent** to initiate Phase 1 (Planning) of the Core Workflow. **Under `session_tool: cursor`, do not `SwitchMode` to plan (`RA-18`); write `IMPLEMENTATION_PLAN.md` at the canonical sprint path in this session.** |
| **2. Pipeline Handoff** | `delegation_conflict` | Read `delegation_mode` from `docs/active_state.json`, written by `session_state.py claim` via `derive_delegation_mode(tool, explicit_mode)`: `--tool cursor` derives `sequential`, every other `--tool` derives `native`, and an explicit `--delegation-mode` overrides the derivation. **A recorded `sequential` is configuration, not an incident**: `agents.md §6` mandates 8 pipeline roles and Cursor cannot instantiate them, so under Cursor this conflict would fire every session by construction, and a report that always fires is a report nobody reads. **The report obligation survives, narrowed to the case that actually warrants it: when the declared mode and the real capability diverge.** `delegation_mode` is a declaration, not a capability probe — a deliberate design decision recorded in `P2`'s commit message — so verifying that reality matches the declaration is this cell's job. If `delegation_mode` reads `native` and the executing agent **cannot** delegate to subagents — a host session policy forbidding it, a non-interactive runner, an unavailable role — it MUST report that divergence to the human at this Phase 2 Pipeline Handoff step, before Phase 1 Planning begins, and await a decision. Substituting itself for the pipeline silently is PROHIBITED regardless of the declared mode. Precedent: a host session whose configuration forbade spawning subagents resolved the conflict in favour of that configuration without saying so, and executed a whole sprint alone; Phases 4 and 7 never ran, `task_scope.md` was never produced — silently disabling `jurisdictional_lock` and `no_interference` across roughly 30 edits — and nothing detected it for twelve commits, because no gate checks whether a phase *happened*. Both gates, once finally run, rejected the branch over defects of exactly the class the sprint had been created to remove. The conflict is legitimate and may well be resolved the same way — what is not legitimate is resolving it without the human knowing it existed. |
