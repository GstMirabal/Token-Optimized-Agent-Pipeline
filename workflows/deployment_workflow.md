# 🛡️ Workflow: Deploy (Deployment Protocol)

The terminal sequence for graduating verified pipeline code from the localized sandbox into production/main branch.

## Execution Flow

| Phase | Step | Action / Constraint |
| :--- | :--- | :--- |
| **0. Sprint Seal Gate** | `sprint_seal_gate` | Run `python3 .agents/scripts/session_state.py require-released` (nucleus: `python3 scripts/session_state.py require-released`). **Exits `2` and deployment stops** when `status` is `SUSPENDED` (session ended with the sprint still open — never publish that tip) or when the ref tip is not exactly `last_close_commit` (no `release` sealed this tip). Pass `--branch ai-sprint/[ID]` when `HEAD` has already moved to a newer claim. A live `IN_PROGRESS` session on an *unsealed* tip is the same refuse. This gate is what makes `close` → auto-deploy safe and `suspend` → deploy impossible. **Hotfix route (Sprint 057 `D4`, `8352421`)**: a release of an `RA-03` hotfix runs `python3 .agents/scripts/session_state.py require-released --hotfix H-NNN` (nucleus: `python3 scripts/session_state.py require-released --hotfix H-NNN`). When the tip is not `last_close_commit`, the flag accepts it only if all four hold: (1) a record `docs/hotfixes/H-NNN-*.md` is tracked at the tip (an untracked file in the working tree does not count); (2) the deployed branch — the `--branch` ref when given, else the checked-out branch — is `hotfix/H-NNN`, or the tip commit subject contains `(H-NNN)` or ends with `#HNNN`; (3) `last_close_commit` is an ancestor of the tip; (4) `status` is not `SUSPENDED`. Any other case, and an id not of the form `H-NNN`, exits `2` as before. **Done-criterion**: exit `0` printing `Deploy preflight passed`. Declaring Phase 0 "not applicable" in a hotfix record is no longer a sanctioned route; a hotfix release runs this form. |
| **0. Git State Gate** | `git_state_gate` | `DevOps Agent` halts execution if `git status --porcelain` detects uncommitted changes. |
| **1. Branch Merge**| `test_audit` | Ensure the Phase 4 `Tester Agent` signature exists (100% passed coverage). |
| **1. Branch Merge**| `broker_precondition` | Before any push, PR, merge, tag or Release step, confirm the GitHub broker MCP server (`scripts/github_broker.py`, `ADR-0025`) lists the tools `push_branch`, `open_pr`, `pr_status`, `merge_pr`, `push_tag` and `create_release` in the session. **Done-criterion**: all six tool names are callable. **Broker not installed or not registered**: every step below that names a broker tool is **blocked**; the agent stops, records the missing tool name in the sprint log, and does not run `git push` or `gh` in its place. There is no fallback to `gh` run by the human (`ADR-0025` section 3, Plan Abort criterion 1; `docs/architecture/GITHUB_BROKER_BLUEPRINT.md` Error handling). Installation and registration are human steps, per the setup guide named in the plan (`docs/guides/GITHUB_BROKER_SETUP_GUIDE.md`, unit A-09). |
| **1. Branch Merge**| `branch_push` | **Default (GitHub remote exists)**: call the broker tool `push_branch` with `branch` = `ai-sprint/[ID]` (hotfix: `hotfix/H-NNN`). The broker refuses `main`, a name with `..`, and any name outside `ai-sprint/*`, `hotfix/*`, `deploy-notes/*`; it never forces. **Done-criterion**: the call returns `{"pushed": "<branch>"}`; a refusal stops deployment. |
| **1. Branch Merge**| `pr_flow` | **Default (GitHub remote exists)**: **(1)** call `open_pr` with `head` = `ai-sprint/[ID]`, `base` = `main`, `title`, and `body` = the squash body below; the return value carries the PR number `[N]` and URL. **(2)** Call `pr_status` with `number` = `[N]` and **observe, in that invocation alone,** `state` = `open` and every required check named in the broker `config.json` `required_checks` present in `checks` with value `success`; a check absent from `checks` is pending, not passed. Repeat `pr_status` as new invocations until that holds. **(3)** Only after that observation, in a **later separate invocation**, call `merge_pr` with `number` = `[N]` and `merge_method` = `squash` (RA-13 Sequential Gates — never chain the status read and the merge in one script or one turn). `merge_pr` re-reads the pull request and refuses unless head is `ai-sprint/*` or `hotfix/*`, base is `main`, and every `required_checks` name is `success`; the broker is the RA-12 gate, so only this step merges into `main`. **Done-criterion**: `merge_pr` returns `{"merged": true, "sha": "<40-hex>"}`; record `sha` as the integrated tip for `release_tagging`. **Squash body (Sprint 057 `C-5`)**: `merge_pr` has no body argument, so the commit body on `main` is what the repository's `squash_merge_commit_message` setting derives from the PR; put the sprint's commit summaries and the `#[Sprint_ID]` suffix in the `open_pr` `body`. **Done-criterion**: `git log -1 --format=%b origin/main` after the merge contains every line of that `body` (GitHub may append trailers such as `Co-authored-by`); a mismatch is recorded in the sprint log as a finding, and no `gh` call repairs it. **Required checks (Sprint 023 `C10`)**: `gh pr checks [N] --watch` cannot gate a merge, because it waits only for checks GitHub has already registered (measured on PR `#45`: it returned having seen `audit` while `Analyze (python)` completed three minutes later). The gate is the explicit `required_checks` list: an unregistered name is absent from `checks` and fails step (2). A broker `config.json` without `required_checks` makes `merge_pr` refuse, which is the fail-closed case. Direct local merge to `main` is only the fallback when no GitHub remote is configured (RA-12 Branch Discipline). |
| **1. Branch Merge**| `deploy_unlock` | For the local-fallback push only: create the marker `deploy_unlock_path()` resolves for the current checkout mode (`scripts/_mode.py is_nucleus()`) — nucleus checkout (`.git` a real directory) → `touch .deploy_unlock` at the repository root; host checkout → `touch .agents/.deploy_unlock` — immediately before the sanctioned `git push origin main`, and **delete it right after**. The `on_commit.py` push guard blocks any push to `main` while the mode-appropriate marker is absent. Before Sprint 053 (`KI-052-9`) the nucleus had no root path and could only satisfy the guard by creating a stray `./.agents/` directory. |
| **2. Environment** | `production_bridge`| Map/mount production environment variables securely. Apply pending `.sql` migrations. |
| **3. Remote Sync** | `ci_cd_handover` | Run local health checks. Confirm the merge landed on origin and remote pipelines triggered. |
| **4. Closure** | `ledger_seal` | Seal the Master Ledger: rename `CHANGELOG.md`'s `[Unreleased]` section to `[vX.Y.Z] - date` (leaving a fresh empty `[Unreleased]`). This commit lands with the release. After the seal commit, as a separate invocation (`RA-13`, never chained with `&&`), run `python3 .agents/scripts/check_role_artifact.py --owner-commit HEAD` (nucleus: `python3 scripts/check_role_artifact.py --owner-commit HEAD`); a non-zero exit stops deployment, and the seal goes to the writer (`doc_orchestrator`) per `ADR-0020` instead. |
| **4. Closure** | `release_tagging` | Call the broker tool `push_tag` with `tag` = `vX.Y.Z` — it must match the `## [X.Y.Z]` ledger section just sealed — and `commit` = the 40-hex `sha` that `merge_pr` returned in `pr_flow`. The broker creates the SSH-signed annotated tag locally (signer `agents-broker`) and pushes it without force; it refuses a name that is not `vX.Y.Z`, a `commit` that is not a full 40-hex SHA, and a `commit` that is not on `main`. **Done-criterion**: the call returns `{"pushed": "vX.Y.Z", "commit": "<sha>"}`. **When the call is refused or the push is rejected** (including a tag ruleset with a `creation` rule and no bypass actor for the App): deployment stops at this step, the refusal text is recorded in the sprint log, and no `git tag`, `git push`, `gh api` ruleset change or human-run bypass command is substituted (`ADR-0025` section 3; the Administration permission is not granted to the App). Do not create the GitHub Release in this step. |
| **4. Closure** | `github_release` | After `release_tagging` returned `pushed` for `vX.Y.Z`, as a **separate invocation** (RA-13 — never chain tag-and-release), call the broker tool `create_release` with `tag` = `vX.Y.Z`, `body` = the full text of `CHANGELOG.md`'s `## [X.Y.Z]` section (read from the file, never generated from the tag message), `name` = `vX.Y.Z`, and `prerelease` = `false`. If that section is missing, do not call the tool: a tag with no ledger section is not a release, and deployment stops. Call it only for a tag that `push_tag` pushed in this deployment, because on a tag that does not exist GitHub would create one from the default branch. **Done-criterion**: the call returns a release `id` and `url`; record both in the sprint log. Tags that predate this step are filled by one `create_release` call per tag, each with its own `## [X.Y.Z]` section as `body`. |
| **4. Closure** | `local_prune` | After the seal and Release land, run `python3 .agents/scripts/branch_sovereignty.py prune` as a **separate invocation**. `close_workflow.md` 5.5 already ran prune **before** the `merge_pr` call of `pr_flow`, so it could not delete the branch just published (`HEAD`, still unmerged). This is the post-merge call: it deletes proven-integrated local heads **and** their `origin` heads when still present. GitHub `delete_branch_on_merge` is independent and may be `false`. |
| **4. Closure** | `baseline_refresh` | After squash-merge is on `main` (checkout `main` at the integrated tip) and the release tag exists: run `python3 .agents/scripts/session_state.py refresh-baseline` (nucleus: `python3 scripts/session_state.py refresh-baseline`). **Done-criterion**: exit `0` and `docs/active_state.json` `last_close_commit` equals `git rev-parse HEAD`. This is the refresh ADR-0002 named — close `release` seals the sprint-branch tip for `require-released`; squash orphans that SHA from `main`. Without this step every post-deploy `/start` re-opens the orphan-baseline warning (Sprint 039). Separate invocation from `local_prune` (`RA-13`). |
| **4. Closure** | `topology_writeback` | **After** `baseline_refresh`, as a **separate invocation** (`RA-13` — never chain the two with `&&` in one line; each is independently observed). Run `python3 .agents/scripts/session_state.py set-topology` (nucleus: `python3 scripts/session_state.py set-topology`). Writes `docs/active_state.json` `topology_version` in the documented format `X.Y.Z-NNN-<status>`, derived from the newest sealed `## [X.Y.Z]` section of `CHANGELOG.md` plus `current_sprint.id`/`current_sprint.status` (Sprint 050 `D7`). This is the write-back that never existed before Sprint 050: `baseline_refresh` updates only `last_close_commit`, and nothing re-derived `topology_version` after a release sealed the version, which is why the field trailed a release. **Done-criterion**: exit `0` and `topology_version` reflects the version just sealed by `ledger_seal`. |
| **4. Closure** | `bridge_lock_refresh` | **After** `baseline_refresh` (separate invocation, `RA-13`). **Both targets, not Cursor alone** — a deploy moves the tip and invalidates every lock, and this repository is worked from both harnesses. For each of `claude` and `cursor`: ask `python3 -c "import sys; sys.path.insert(0,'scripts'); from bridge_state import bridge_stale; print(bridge_stale(__import__('pathlib').Path('.'), '<target>', nucleus=True))"`. **False** → write `.bridge_<target>.lock` to `HEAD` only. **True** → `python3 scripts/install.py --target <target>`. **Never refresh a lock over a mirror that is stale**: that is exactly the Sprint 041 defect reintroduced from the deploy path — a lock matching `HEAD` makes the next `/start` see triage (a) and skip the install forever. **Done-criterion**: for each target, lock text equals `git rev-parse HEAD` **and** `bridge_stale` is false. Avoids the first post-deploy `/start` discovering a stale lock solely because the tip moved (Sprint 040). Until Sprint 041 this cell was conditioned on *"If `session_tool`/operators use Cursor"* and touched only `.bridge_cursor.lock`, so the Claude bridge had no maintenance path at any point in the lifecycle. |

> [!NOTE]
> **GitHub operations run through the broker (`ADR-0025`)**: push of the sprint branch, PR, status read, merge, signed tag and Release are calls to the broker's MCP tools (`scripts/github_broker.py`), which holds the credential; no command is excluded from the sandbox. The agent runs no `gh` and no `git push` for these steps. Commands outside the broker's six tools that still call `gh` (`scripts/branch_sovereignty.py prune` in `local_prune`): see the single table `rules/project_topology.md` section 4, `gh` row; residual risk: the "After a sandboxed agent session" row of that table.
