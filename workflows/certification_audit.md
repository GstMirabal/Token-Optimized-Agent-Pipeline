# 🛡️ Workflow: Global Certification Audit

This workflow performs a comprehensive health check of the repository, ensuring it meets the 100% Core compliance standards of the Universal-Agents framework, regardless of the underlying stack or ORM.

## 📋 Execution Steps

### 0. Scoping & Roadmap Initialization
- **Map Implementation:** Identify implemented modules vs. uninitialized boilerplate.
- **Incremental Audit:** Determine which areas have changed since the last certification.
- **Define Target:** Create or update `docs/CERTIFICATION_ROADMAP.md` listing the modules to be audited in this session.
- **Exclusion Zone:** Explicitly exclude `.agents/governance/` and other metadata-only folders from automated scans (Linting, Typing, SAST).
- **Skip Certified:** Exclude modules already marked as "100% Core Compliant" unless they have significant logic changes.

### 1. Environment & Configuration Check
- Verify runtime environment (e.g., Python, Node.js, Go) and dependency versions.
- Run framework-specific configuration validation (e.g., `django check`, `npm run build`, or custom health checks).
- Ensure required environment variables (`.env`) are present and valid for the target environment.

### 2. ORM & Database Schema Integrity
- **Migration Check:** Verify if there are pending schema changes not yet captured in migrations (e.g., `makemigrations --check`, `prisma migrate status`).
- **Sync Validation:** Ensure migration history is linear and matches the current database state.
- **ORM Audit:** Check for missing indexes, N+1 query risks, or inconsistent relationship definitions in models within the **implemented scope**.

### 3. Code Quality & Static Analysis
- **Linting:** Run standard linters to audit style and logic rules (e.g., `Ruff`, `ESLint`, `Flake8`).
- **Typing:** Verify strict type compliance (e.g., `Mypy`, `TypeScript`, `Pyright`).
- **Complexity:** Review cyclomatic complexity and ensure modularity standards are met for the **scoped modules**.

### 4. Security & Production Readiness
- **Dependency Scan:** Audit for vulnerable packages (e.g., `Safety`, `npm audit`, `Snyk`).
- **SAST Audit:** Perform Static Application Security Testing on the source code of the **implemented part** (e.g., `Bandit`, `Semgrep`).
- **Cloud/Deploy Audit:** Verify production settings (SSL, headers, secure cookies, debug off).

### 5. Documentation & Technical English
- **Sanitization:** Scan for non-technical strings or locale-specific remnants in the **current implementation**.
- **Standard:** Ensure all docstrings and comments follow the English Technical Standard (e.g., Google Style or JSDoc).

## 🏁 Certification Report
The result of this workflow must be updated in `docs/CERTIFICATION_ROADMAP.md` (as a persistent record of compliance) and the status reflected in `task.md`.
