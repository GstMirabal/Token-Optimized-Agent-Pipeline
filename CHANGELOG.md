## [4.7.0] - 2026-08-17

### Added
- **Every agent profile declares the model tier it runs on, and two gates keep the map true** (`agents/*.md`, `config/model_tiers.json`, `scripts/check_model_tiers.py`, `scripts/detect_new_models.py`). Upstream finding `#12`, routed by a host and adopted nowhere: **0 of 13 profiles declared a model**, so every role ran at the session's top tier — the deterministic ones included — while `agents.md §6` mandates eight roles per pipeline pass and usage reports attribute **100% of spend to subagent-heavy sessions**. Roles are now classed `gate` / `author` / `mechanical`, named by what the role does rather than by rank, so the map survives a lineup change. **Two fields, not one, and the reason is recorded because it is not obvious**: a profile declares `model:` (a family alias, applied natively by the harness) *and* `tier:` (the intent). Tier-only was rejected — Claude Code ignores frontmatter keys it does not know, so the file would have claimed one tier while the subagent ran on the session default, the most expensive one. **The gates stay at the top tier and that is not negotiable**: across four consecutive host sprints every central defect was found by a gate and nothing else, several after surviving their author's own verification. Fable 5 is excluded with its reason (2× the cost of Opus and 30-day retention, so it does not work under ZDR) and Haiku 4.5's 200K ceiling is declared, since `mechanical` inherits it. **Prices are deliberately absent from the config** — they exist on no disk here, so a copy would be stale the day it was written; `verified_at` makes the gap age visibly instead of rotting quietly. The tier table was itself about to be written from memory, and the `claude-api` reference trigger caught it: Fable 5 turned out to cost twice Opus rather than being a cheap top tier.
- **A new, deprecated or retired model is noticed from the catalogue already on disk** (`scripts/detect_new_models.py`). The `claude-api` skill Claude Code bundles ships `shared/models.md` with alias, full ID, context window and status, and its path encodes the CLI version — so the catalogue refreshes exactly when the tool updates, with **zero network, credentials or dependencies**. Severity is a ladder rather than a switch: a **new alias is proposed** (a model is not adopted for existing), a tier turning **Deprecated is proposed with its retirement date** (there is room, but the clock is running), and a tier turning **Retired fails the build**, because that is not a judgment call — a retired model returns 404. Propose what needs judgment, block what is a guaranteed failure.

### Fixed
- **Two design defects in this sprint's own mechanism, both found by verifying rather than reviewing** (`scripts/detect_new_models.py`). Recording them because a passing test suite would have shown neither. **First, the parser attributed one model's retirement to another.** The catalogue holds a second table mapping user phrasing to suggested models — `| "sonnet 3.7" | Retired — suggest claude-sonnet-5 |` — and a parser scanning each row for any alias and any status word recorded `claude-sonnet-5` as `Retired`. Wired to the severity ladder, **that false verdict fails the build over a tier that is perfectly current**: a correct datum in the file, read wrongly, producing a verdict that reads as authority — the defect class this whole program pursues, committed inside the mechanism that pursues it. The discriminator is now structural — a catalogue row has the alias **alone in its second cell** — so the phrasing table is rejected by construction rather than by a denylist, and the hermetic fixture reproduces that table deliberately, because without it the broken parser passes. **Second, the gate would never have fired in CI.** The bundled catalogue lives in a per-user temp directory the system clears and CI never has, so a gate reading it directly would have reported green there forever — `RA-16`'s exact concern, inside the sprint building the gate. `catalog_snapshot` in `config/model_tiers.json` is therefore the **durable, committed copy and the gate's only source**, so `--check` returns the same verdict on a laptop and in CI; reading the bundled file is the opportunistic half that proposes refreshing the snapshot, and it says so when absent rather than implying the map was checked against something newer.

### Changed
- **`token_economy_agent` owns the tier map, and rejects the selector agent by its own rule** (`agents/token_economy_agent.md`). Three charter rows: `tier_ownership` (the map and both gates), `tier_escalation` (when a task's difficulty diverges from its role's default, the role **proposes** in `task_scope.md`, the record notes it, the human sees it — a declaration, not a dispatch), and `no_selector_agent`. That last one matters: a per-task model-selector agent was requested and is rejected **by this profile's own `burden_of_proof`**, which demands naming a concrete deterministic alternative before refusing. The alternative exists and is named — the static tier table, which costs nothing — and a subagent launched per task to choose a model is precisely the recurring mechanism delegated to agent judgment that the profile's `responsibility` row rejects, while spending the very unit of cost the tiering reduces.

## [4.6.0] - 2026-08-17

### Added
- **The framework can measure what a session costs, and bound it** (`scripts/session_cost.py`, `rules/token_economy.md §3.1`, `scripts/session_probe.py`). `loop_governance.md` had declared its token budget advisory with this reason: *"no agent reads its own spend reliably, and making it binding would force a field nobody can fill truthfully"*. That premise ended here — spend is read from the transcript Claude Code already writes, with zero network, credentials or dependencies. **The unit is the context cycle, not the session, and re-measuring before building is what established that.** The finding that ordered this whole program claimed cost grows monotonically with message position (quartiles 7/15/23/54%); over a full session the quartiles are 157K/681K/245K/485K, because compaction resets the window four times. The original figures were real but came from the first 400 messages, entirely inside cycle 1, at a scope never declared — the fifth instance of program risk `J6`, and the most expensive, since that figure set the queue order. **The conclusion survives and strengthens**: cost is the area under the sawtooth, and compaction resets the x axis without reducing it. Four resets happened and the session still spent 423M `cache_read`; cycle 2 is the proof, with **113 messages costing 99.5M** — nearly matching a 414-message cycle — because it climbed to 995K. **Cost tracks peak height, not message count.** Two things the corrected shape buys that quartiles could not: the reset point is **22,174 tokens, identical three times**, turning break-even from an estimate into an observed constant; and the hard threshold would have fired in **3 of the 4 cycles**, validating the calibration provided the ratio is measured per cycle — against the session's first turn it collapses at the first reset and never fires again, which is why four propagation sites were corrected with it (`RA-14`). The bound is soft at 5× and hard at 15×; the soft one records without acting while the calibration distribution builds, because a binding threshold means the sprint always closes at the bound and the natural close is never observed. Live acceptance: the meter reproduces 38.3×, 44.9×, 14.0× and 30.0× on the session that drafted it.
- **A session can end without sealing the sprint it was working on** (`scripts/session_state.py`, both workflows). The bound is binding and fires mid-sprint, so the protocol needed an exit that does not lie — and had none: two states, `IN_PROGRESS` and `CLOSED_SUCCESSFULLY`, neither meaning "the session ended, the sprint continues". `suspend` sets `SUSPENDED` and **deliberately does not write `last_close_commit`**, because that field means "the commit where the last close sealed" and writing it at a session boundary would set a false baseline and blind the detector Sprint `024` repaired. **Verifying before building corrected the design**: `claim()` blocks only on `IN_PROGRESS`, so a suspended anchor already passed without `--takeover` — the collision guard permitted the resume structurally, and what was missing was that nothing ever wrote the state and that resuming left no trace, making a sprint spanning sessions invisible. `claim` now reports the resume and increments `session_count`. `close_workflow.md` states the asymmetry where it gets miswired rather than in a document of its own: the program roadmap's own Sprint `027` design wired `SessionEnd` to `release` and would have written a false seal at every session end. Seven tests cover both directions of each guarantee; the one that matters is the abort criterion, hermetic rather than manual — after suspending, `detect_drift` still reports the unrecorded work.
- **A plan drafted in an IDE lands in the repository** (`claude/settings.hooks.json`, `docs/plans/README.md`). The failure that opened this program: a host lost an approved Implementation Plan to ephemeral storage. `plansDirectory` is declared in the bridge template and points at `docs/plans/`, **deliberately not at the canonical sprint path**, because files there carry IDE-generated names while the plan `triple_lock` names as its first lock is authored at Phase 1 — treating a generated name as that artifact would make the lock unverifiable, since `close_workflow.md` Phase 2.6 asks whether *this sprint* left its plan. Two limits are written down rather than left to be discovered: Cursor does not read `settings.json` (Sprint `026` `P4`), and neither does the close gate (Sprint `023` `C0`). Verified against Claude Code's changelog before being written, not recalled.

- **A sealed commit was reported as drift, and it blocked the pipeline's own opening command** (`scripts/detect_drift.py`, `workflows/start_workflow.md`). The check compared `last_close_commit..HEAD` and called everything in the range "outside the protocol". That range mixes two populations: work nobody recorded, and work **sealed into a released ledger section** — `deployment_workflow.md` Phase 4 empties `[Unreleased]` and tags, without touching `last_close_commit`, so recorded commits keep landing after the last close. The consequence was structural, not occasional: **the first `/agents:start` after every deployment printed "the [Unreleased] section is empty, so none of it is recorded"** on a clean tree where the ledger described everything. Measured at `v4.4.0`: exit `2`, while `#37` sits at `CHANGELOG.md:51` and `a3c6f5f` *is* the commit that sealed it, both ancestors of the tag. The remedy the protocol named did not apply either — `reconciliation_workflow.md` Phase 2 finds every commit covered, Phase 3 forbids inventing entries, Phase 8 has nothing to declare. The range is now split against **sealing tags** (tags whose version owns a `## [X.Y.Z]` section, derived not hardcoded — `v3.4.0` and `v3.5.2` own none and seal nothing) and the exit code follows **the action required, not the severity observed**: `S` all covered → `0`, `M` partial → `2` listing only the uncovered, `U` none covered → `2`, `A` uncovered with `[Unreleased]` non-empty → `2` because reachability cannot prove coverage per commit, `R` no releases at all → `2`. **`R` returning `2` is a correction the test suite forced**: an earlier design passed there on the grounds that nothing was measurable, and the pre-existing `test_commits_after_the_sealed_close_are_drift` refuted it — a repository with commits after the baseline and no releases is the Phase 018 scenario in its early form, and passing it would have whitewashed the exact drift this check exists to catch. It had never fired only because `last_close_commit` was introduced in Phase 019 and its one value was set by hand during that phase's reconciliation; the first normal close to write one would have been this sprint's. The check now falls back to `git merge-base` and **states the substitution** instead of listing the whole history since the fork point.

- **The guard against host contamination could not see it, and four mechanisms were dead behind the same cause** (`.gitignore`, `agents.md §5`, `Makefile`, `docs/active_state.json`, `docs/sprints/024-core-pipeline/`). `.gitignore` excluded the pipeline's own records — `docs/sprints/`, `docs/active_state.json`, `implementation_plan*` in eight extensions, `task_scope.md` — to keep a host's work out of the shared nucleus when `.agents` is a submodule. **That intent is `RA-15` and is right. The instrument was inverted.** `close_workflow.md` `submodule_purity` guards the submodule with `git -C .agents status --porcelain` is clean, and **that command does not list ignored files**: verified by creating a file under `docs/sprints/` and watching the command return completely empty. The exclusion did not protect the nucleus from host contamination — it hid the contamination from the one check built to catch it, which is the same defect this whole sprint is about, committed by the defence itself. Four consequences, each measured: `submodule_purity` blind; `scripts/loop_guard.py` unable to read the `task_scope.md` it measures progress from; `close_workflow.md` Phase 2.6 with no artifacts to demand; and `rules/documentation_standard.md:94` — which mandates a **git-tracked** `graph_stats.json` *inside the canonical sprint directory* — impossible to satisfy, so the freshness gate's delta series could never accumulate and its `BLOCK` (needing ≥5 deltas) could never arm. The line drawn is **content versus session state**, not sprint-records-yes-or-no; the durable half is recoverable from the tracked sprint record, the ledger and the tags, which is what this sprint built. ### Fixed

The verification list in the guide's §4 was corrected to the same 13.
- **A skipped pipeline phase left no trace, and nothing could detect one** (`workflows/start_workflow.md`, `workflows/close_workflow.md`, `scripts/docs_freshness_check.py`). Every control here inspects the *content* of what was written — `on_commit.py` validates commit shape and scans for secrets, the freshness gate compares documentation against the graph — and none asks whether the phase responsible for a file executed at all. A host ran a whole sprint without Phase 4 (Roadmap Review) and Phase 7 (Double Gate); `task_scope.md` had been produced by every sprint for thirty cycles, and its absence raised nothing across twelve commits. The omission was caught by a human asking, not by a gate. **The cost was not procedural**: `jurisdictional_lock` and `no_interference` are both applied by *reading* `task_scope.md`, so skipping the phase that writes it disabled two isolation rules while they still appeared to be in force, and roughly thirty file edits proceeded under them. The root cause was a **conflict of authority, not negligence**: the agent's session configuration forbade spawning subagents while this framework requires delegation, and it resolved that silently in favour of the session policy — so Phase 2 now requires reporting an inability to delegate *before* Phase 1, the freshness gate reports a missing artifact **by the phase that produces it** rather than by filename, and `close_workflow.md` Phase 2.6 refuses to seal a sprint whose record proves neither phase ran.
