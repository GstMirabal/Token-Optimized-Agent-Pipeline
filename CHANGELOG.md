## [Unreleased]

Everything below was surfaced by installing the published framework into three real host repositories, not by internal audit. All of it was green in the nucleus and broken in the field — recorded as Phase 18 in `docs/roadmaps/core/pipeline/018-post-publication-field-hardening.md`.

### Added
- **Two protocols that sit outside the sprint pipeline**, for a repository the framework has not handled before: `workflows/repository_hardening_workflow.md` (`/agents:harden`) and `workflows/reverse_documentation_workflow.md` (`/agents:revdoc`). Both cover work that happened on every host and was reconstructed from memory every time, which is how steps get skipped. **`harden`'s content is its ordering** — branch protection blocks history rewriting, and a required status check that never runs makes every pull request unmergeable, so protection is configured from check names observed on a real run rather than from names assumed in advance. It also records what cost time to discover: private vulnerability reporting is off by default (so a `SECURITY.md` pointing at the Security tab documents a channel that does not exist), `secret_scanning_non_provider_patterns` returns `200` and stays disabled on a free plan with no error, Dependabot alerts lag a version bump (verify against a clean install, not the manifest), and `community/profile` reports `issue_template` as `null` whenever templates live in a directory — which is the current form. **`revdoc` puts the graph first** as the *input* to reverse engineering rather than a check applied afterwards, because writing first and validating later produces errors you then go looking for. Its contract-writing phase is what earns its place: reading each entry point end to end surfaced both capital-risk findings in a trading relay, neither of which was visible at blueprint level. It also records why a path check must run against every prefix a repository has ever used — one host shipped a guide whose first command referenced a directory deleted in the same sprint, and the check that would have caught it was scoped to the new prefix and reported clean.
- **`unambiguous_action` indexed into `agents.md §1`**. It complements the existing `restrictions` rule by naming what vagueness actually consists of — deictics, verbs that state no operation, adjectives used as acceptance criteria, magnitudes without units, passives that hide who decides — because the prior rule prohibited vagueness without defining it. Precedent: in one plan `here` resolved to two different repositories in the same document, and `leave it perfect` was the exit criterion of its largest phase.
- **Native `pre-commit` hook installed by the bridge** (`scripts/install_claude.py`). The secret scanner ran only as a Claude Code `PreToolUse` hook, so it saw only commits the agent made through its Bash tool; a commit typed in a terminal, made from an IDE, or produced by any other tool bypassed it entirely — and in a repository with a human in it, those are most of the commits. None of the three audited hosts had a native hook, and `.git/hooks/` is not versioned, so the bridge installer is the only place this can come from. Verified end to end rather than by inspection: with a secret staged and a commit made from a terminal, the hook fires and the commit is refused — no object is created. An existing pre-commit hook belongs to the project and is never overwritten; the installer prints the line to add instead. **This shipped together with the `SECRET_ASSIGNMENT` fix below by necessity**: with the old pattern list, a staged `MASTER_KEY = "<literal>"` passed the native hook exactly as it passed the agent hook, so landing the coverage alone would have widened the net over a hole and produced a more confident false green.
- **`docs/assets/logo/social_card.svg`** — a 1280x640 source for the GitHub link preview, composed natively for the 2:1 card rather than letterboxing the 4:1 banner, which left dead space and ran the banner's own hairlines across the middle. Same design system as the banner (paper gradient, brass rail, Georgia display, tracked tag boxes, subagent-graph emblem). The PNG is uploaded through GitHub Settings, which has no API for that field; this SVG is the regenerable source.

### Fixed
- **The secret scanner could not tell a leak from a lookup** (`hooks/on_commit.py`). `audit_secret_shielding` matched the bare substrings `API_KEY =`, `SECRET =`, `PASSWORD =` and `PRIVATE_KEY` against the uppercased file, which flags every legitimate *read* of a secret — `password = request.data.get("password")`, `db_password = db_components.get("POSTGRES_PASSWORD")` — something no project handling authentication can avoid. One host hit seven such false positives in a single commit and had no way to pass the gate, so the guard blocked all work while catching nothing. The right-hand side is what separates a leak from a lookup: the scanner now requires a secret-named identifier assigned a string **literal**, and skips environment interpolation placeholders (`$VAR`, `{VAR}` — the pattern `RA-09` sanctions in `config.toml.example`), obvious placeholders (`example`, `changeme`, `your-`, `dummy`), values shorter than 8 characters, and test fixtures/factories where credentials are hardcoded by design. Detection also widens to `MASTER_KEY`, `SIGNING_KEY`, `ACCESS_KEY`, `PEPPER` and `CREDENTIAL` — the previous list missed all of them, including `MASTER_KEY`, the primary encryption secret of the project where this was found.
- **The documentation freshness gate could not fail, and could not see host code** (`scripts/docs_freshness_check.py`) — four defects, found while auditing three hosts that all reported it green. **It could not fail**: its only exit was an unconditional `sys.exit(0)`, and `FreshnessReport.has_block` was defined and referenced nowhere, so the verdict was computed on every run and consulted on none — while `documentation_standard.md §4` describes the script as gating `SESSION LOCKED`. Every green run of it, in any host, was a constant rather than a verification. **It skipped its only blocking check in silence**: the structural-change delta is the sole producer of a `BLOCK` and runs only when `current_sprint.last_audit_sprint` is readable, so a host declaring `current_sprint_id` at the root got no check and no word about it; it now warns. **`root: "."` matched the framework and missed the host**: taken literally, `source_file[len(root):]` removes the first character of every path, so `users/views.py` became `sers/views.py` and matched nothing while `.agents/hooks/x.py` became `agents/hooks/x.py` and matched — the submodule was reported as a container of the host, needing a C4 Level 3 the host cannot write, while the host's actual code was invisible. That is exactly backwards, and it is why one host carried a phantom `app/agents` warning. **Absolute paths produced containers with empty names.** Verified against all three hosts before and after; none had a `BLOCK` finding, so making the exit code real breaks nothing today — which was the check worth doing before touching it. Five tests added (suite 60 → 65), and the fourth defect was found by one of them rather than by reading.
- **Three `RA-14 PATCH_PROPAGATION` violations left by the protocols PR**, all repaired during this closeout: `README.md`'s "At a Glance" row still read `10 protocols … 11 slash commands` while the same PR updated the prose two sections below it to "all 13 commands" (actual counts re-verified against the tree: 12 workflows, 13 commands); `docs/guides/AGENTS_SLASH_COMMANDS_GUIDE.md §3.2` documented 11 commands and never mentioned `/agents:harden` or `/agents:revdoc`, despite being the reference `README.md` points readers to for all 13; and the guide's §3.1 retrofit sequence still ended at `/agents:pipeline` while `README.md`'s parallel sequence had gained the `harden` → `revdoc` → `pipeline` ordering. The verification list in the guide's §4 was corrected to the same 13.

## [3.5.0] - 2026-07-26

### Added
